# Tracks: keys and commands

`tracks` opens the pane. `cmd+shift+h` (`rex/tracks.lua`) switches Rex to the desk session, the desk agent with this pane beside it (started when it is not running, and kept first in the session list); pressed there, it goes back to the session you came from. `cmd+shift+k` jumps to the track that needs you most. `?` in the pane lists the keys.

## The Needs you band

Above the list, full width (also in the one-column layout), the pane shows what needs you: `NEEDS YOU` with the number of open decisions (one per row, the same number as the header's `◆ N for you`), then one row per decision, then a dim rule. The rows come from the tracks that need you, in `tab` order: an ask on an agent that is not working, a blocked agent, an error; parked tracks never, a thread only when blocked or in error. A row reads `◆ track  N  question  → recommendation  age`: the track's name sits on its first row only, a blocked or error row shows the state and what the agent says in the question's place, marked `▲` (a prompt), `?` (a question) or `✕` (an error), so only asks carry `◆`, and the track you have selected carries `▌` on its rows. When the pane is too narrow the age goes first, then the question is cut with `…` down to 28 columns, and only then the recommendation, at a word. At most 6 rows, and the whole band keeps to a third of the body: more end in `+N more · tab walks them`. Asks on tracks whose agent is still working are not yours yet: one dim line, `not yours yet  NAME ◆N · …` (left out on a pane under 17 rows). With nothing for you the band is `Nothing needs you` and the rule, so the list below never moves; on a pane under 13 rows tall it is hidden. The list's `◆N` column is dim, since the band carries the colour. Help, the handled log and the new-track box hide the band. With `tracks.db` the rows read the `questions` table instead of the cards' asks (a card without the database keeps the paragraph above): one row per open question, `◆ track  D12  question  → recommendation  age`, where `D12` is the question's id and the recommendation is the recommended option (`→ 2 orders`) or, when the recommendation names no single option, its `Recommend:` text. A question the desk or a check raised is always yours, also on a track whose agent works. An agent's ask becomes a question each time the card is written (see `tracks decisions` below), so its `D` id stays the same while the agent rewrites the card with that ask unchanged.

**Answering a question.** `a` gives the band the focus for the selected track's question (`↑` `↓` take it away; `tab` and `enter` work as before); then `enter` takes the recommended option (a question with none says so and does nothing), `1`-`9` pick an option, `r` answers in words (`enter` queues it, `esc` cancels), `[` and `]` choose between a track's questions, `space` shows or hides its options, evidence and links, `o` opens its first link (the card's links when it has none), `g` opens the track in Rex as `enter` does without the focus, `esc` gives the focus back. An answer is not sent at once: the row turns into `✓ D12 merge now · 4 s ████░  z undo` and counts down 5 seconds; `z` within them takes it back and nothing was sent; quitting the pane before they pass takes it back too. When they pass, an answer to an agent's question is typed into its agent the way `r` and `1`-`9` always did (refused while the agent works: the footer says `Not sent` and the question stays open), and an answer to a desk or check question is only recorded, for `tracks wait` to hand to the desk.

## Keys in the pane

| Key | What it does |
|---|---|
| `↑` `↓` `j` `k` | move between tracks |
| `tab` / `shift+tab` | next / previous track that needs you (blocked, then error, then asks, then done; focus first, longest waiting first), wrapping |
| `enter` | open the track in Rex: select its session, focus the agent. A track with no live session asks to start an agent (`y`) |
| `o` / `O` | open the first link; `o` again within 2s, or `O`, opens the next |
| `a` | answer the selected track's question in the band: `enter` recommendation, `1`-`9` option, `r` words, `z` take back within 5s, `[` `]` choose, `space` evidence, `o` link, `g` open the track, `esc` back (see The Needs you band) |
| `1`-`9` | accept ask N (agent ask: opens the reply prefilled; check ask: applied on the card, and a yes on a tier 1-2 track tells its idle agent to continue). While the agent works on an answer you just sent, the detail says `Answered 1, 2 · agent working` and the digits only say so in the footer; `r` still replies |
| `r` | reply to the agent (`enter` send, `esc` cancel, `ctrl+u` clear) |
| `f` `b` `w` `p` | set the mode: focus, background, waiting, parked. The cursor stays on the track and the footer says `Moved NAME to WAITING`, or `NAME is already in WAITING`. Parked tracks sit in the PARKED group at the bottom; their agents are not polled and their asks never count as needing you. `f`, `b` or `w` on one brings it back |
| `n` | new track: say what you want (`enter` start, `esc` cancel, `ctrl+u` clear); the box grows to 8 rows as you type. The name comes from your words (a link counts for its topic, a ticket key stays whole); the agent starts in `$TRACKS_DEFAULT_DIR` or `~/Developer`, then finds the repo, sets the tier, and may rename the track once |
| `d` | the desk: switch Rex to the desk's agent when it runs; otherwise start one, as `tracks desk start` does (a Rex session `desk` with the desk's Claude on the left and this pane on the right), and switch to it. From the floating pane it starts the desk even over a track's window, which `tracks desk start` run in a track's session refuses; the float closes once Rex shows the desk. The desk talks to you in its chat; the pane keeps its handled log (`h`, with `u` to take back an answer or a start) and its notes in each track's detail |
| `x` | close the track: the footer says what it does: the card is always archived; the session ends if nothing in it can be lost, and the footer says it stays when its agent is not at rest (working, blocked) or another track uses it. `y` confirms, `n` keeps. On a lead the footer also says how many threads close with it and how many sessions stay; `y` closes each thread under the same rules, then the lead |
| `space` | show or hide a lead's threads (folded by default). On a thread it hides them and selects the lead. A thread's asks never count toward "N need you", `tab` or `tracks next`: they are for its lead. A thread blocked or in error does count, and `tab` unfolds its lead to land on it |
| `pgup` `pgdn`, wheel | scroll the detail |
| `shift`-drag | select text |
| `?` | the key list, with the last error and when it happened; any key closes it |
| `esc` | cancel; closes the floating pane |
| `q` `ctrl+c` | quit |

## Keys in prism tui

`prism tui` is the desk window (desk v3, option B): sessions on the left, the desk's conversation in the middle, the board on the right. It is a client of `prism server` (docs/serve-api.md) and reads `$TRACKS_HOME/serve.json`; `prism tui --fixture FILE` runs it on a snapshot file instead (`mock/serve-fixture.json`, with `serve-transcripts.json` beside it), answering actions in memory. From 150 columns it shows all three columns; from 100 the conversation with the board beside it, and the sessions in the board's place while they have focus; below that only the focused column. Screens: docs/desk-ui.md.

The middle column takes what you type whenever it has focus: letters, `q`, `z` and `?` go into the composer there. New desk entries never move the composer or its text: while you type or have scrolled up, they wait under `▾ N new` until you send or scroll down. A question selected on the board (or with `r`) turns the composer into that question's: its options with the recommendation marked, and room to answer in your own words. Every answer waits 5 seconds with a countdown before it is sent, and `z` takes it back.

| Key | Where | What it does |
|---|---|---|
| `tab` / `shift+tab` (`ctrl+→` / `ctrl+←`) | anywhere | next / previous column |
| `↑` `↓` `j` `k` | sessions, board | move; in the conversation `↑` `↓` `pgup` `pgdn` and the wheel scroll |
| `enter` | board | on a question, take the recommendation; on a session, show its transcript; on LANDED, unfold it |
| `1`-`9` | board | pick option N of the question |
| `r` | board | answer the question in your own words in the composer |
| `enter` | composer | send to the desk; with a question, your words as the answer, or the recommendation when the box is empty |
| `alt+1`-`9` (`ctrl+1`-`9` where the terminal tells them apart) | composer | pick option N of its question |
| `alt+enter` / `ctrl+j` | composer | new line |
| `ctrl+u` | composer | clear |
| `esc` | composer, sessions, a transcript | in the composer, from a question back to the desk; elsewhere, back to the desk's chat |
| `z` / `ctrl+z` | anywhere (`z` in the composer only when it is empty) | take back the newest answer still counting down; words go back into the composer |
| `enter` | sessions | focus the conversation on the selected row: the desk, a session's transcript (read-only), or a track's card |
| `space` | sessions, board | fold or unfold PARKED, LANDED |
| `t` | sessions, board, a transcript | take the session over: its owner becomes you and it opens in Rex (`claude attach`); the footer gives the command when Rex is not there |
| `g` | sessions, board, a transcript | give the session back to the desk |
| `o` | sessions, board, a transcript | open the question's or the track's first link |
| `?` | outside the composer | the keys; any key closes them |
| `q` / `ctrl+c` | `q` outside the composer | quit |

Opening a finished session you have not seen marks it seen (`POST /v1/sessions/ID/seen`).

When `claude agents` fails, hosts stay as the hooks wrote them and the table says so. `--json` prints `{"schema":1,"generated_at":…,"liveness":bool,"sessions":[…]}`; `liveness` is whether `claude agents` answered. | `tracks bind NAME` | the track agent's first command: makes the card if there is none (as `tracks new NAME --dir "$PWD"` would), sets `rex_session:` from `$REX_SESSION` and prints the card. Prints `closed` for a closed track and `renamed to NEW` for a renamed one, and then changes nothing |
| `tracks card NAME` | the track agent's card update, fields on stdin (see `docs/v2.md`, Card writes); `role: lead` makes a track a lead (empty clears it; refused on a thread; needs `tracks.db`). It goes through the same path as `tracks decide`, which answers a permission question the same way (option number or `--text`). By `desk` when the asking session's parent runs it, else `emil`. The desk may answer only Allow once or Deny (words included), only on a tier 1 or 2 track, and only while it owns the session: anything else by `desk` is refused and stays Emil's. The answer closes the question; the waiting hook passes it on. The desk's answer is logged in its handled log as `answered`. A closed question is refused. Prints `answered D12: ANSWER`. Needs `tracks.db` |
| `tracks hook` | the Claude Code hook (reads stdin, prints nothing). It logs attention events and, with `tracks.db`, keeps the session's row in `sessions` current for interactive and background (`claude --bg`, told apart by `CLAUDE_JOB_DIR`) sessions: SessionStart upserts it (host `rex` or `background`; source startup or resume sets status `idle` and clears `ended_at`), UserPromptSubmit sets `working`, Stop sets `done` and `last_answer` (the payload's `last_assistant_message`, cut at 4000 characters), Notification (not the idle one) and PermissionRequest set `blocked` with `waiting_for` (`permission: TOOL INPUT` for a permission request), SessionEnd sets host `stopped`. PreToolUse (the session's own agent, not a subagent's tool calls) sets `working` and the session's `activity`; a subagent's PreToolUse sets a `blocked` session `working` again while the session's own agent waits on the Agent tool, since its prompt was answered (`TOOL: command, file name, description or pattern`, one line of at most 80 characters); Stop clears it. The Agent tool's PreToolUse queues its description, SubagentStart takes the oldest queued description as the subagent's name (else its type) and records it `working`, SubagentStop marks it `done`; Stop marks the rest done unless its `background_tasks` lists some, and the next prompt drops the done ones (`session_subagents`, schema 14). A prompt into a session owned by `desk` sets owner `emil`, unless it equals the text of a message delivered to that session in the last 10 minutes (the start prompt `tracks start` gave it counts as one). When a session the desk owns stops, Stop writes a `report` message to its parent session with its last answer; when it turns blocked, the first Notification or PermissionRequest writes one with what it waits on. Headless runs (`claude -p`) are skipped |

### Exit codes

`tracks open NAME` and `tracks resume NAME` (one track) keep their stdout and also set the exit status, so a caller need not parse it:

| Code | `open NAME` | `resume NAME` |
|---|---|---|
| 0 | Rex was switched to the session (a block that could not be focused still counts) | the agent was resumed or recreated, Claude already runs, or `--dry-run` |
| 1 | any other error: bad name, no card, usage | a track failed to resume, or bad usage (`--all` also: another resume holds `resume.lock`) |
| 2 | the card has no `rex_session`, or Rex has no such session | nothing to resume, or the card's session id matches more than one session |
| 3 | Rex did not answer, or refused to select the session | skipped: could not ask Rex |
| 4 | | skipped for any other reason (the directory is gone, no idle shell, no terminal pane, another resume holds `resume.lock`, …): the agent is not back |

A manual `resume` (by name or `--all`, not `--dry-run`) takes `resume.lock` in the tracks state directory, the lock the server-start run holds while it types. It does not wait: when the lock is held it prints `NAME: skipped (another resume is running; try again in a minute)` and exits 4 (`--all`: exits 1, and the line says `resume:`), typing nothing.

After a resume by name that brings the agent back, Rex is switched to its session and block, as `open` does; a failed switch is printed and does not change the exit code.

`links:` on a card: comma-separated ticket keys (`ABC-123`, opening where `TRACKS_ISSUE_URLS` says for their project) and `http(s)` URLs.
