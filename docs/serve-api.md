# prism server: the API (draft, 2026-11-24)

Status: the contract steps 5 (EMI-380, the server) and 6 (EMI-381, the native app) build against. Written before either, so both can start at once; change it in this file first when either side needs something else.

## Transport

- `prism server` listens on `127.0.0.1` on a port it picks, and writes `$TRACKS_HOME/serve.json` (mode 0600): `{"url": "http://127.0.0.1:PORT", "token": "…", "pid": N, "version": 1, "build": "…"}`; `build` names the binary serve started from (write time and size), and `tracks desk` prints it beside the installed build.
- Clients start serve themselves: when `serve.json` is missing, its pid is dead or the connection is refused, the app and `prism tui` run `prism server` detached (new session, stdin from /dev/null, output appended to `$TRACKS_HOME/serve.log`, never `--force`) and wait up to 10 s for `serve.json`. A serve that exits with an error (for example the refusal while an interactive desk runs in Rex) is shown to Emil as it said it, with a retry; a serve that lost the `serve.lock` race exits and the client connects to the winner. `--fixture` starts nothing.
- The app runs that check before every connection, not only at launch, so a serve that was killed or exited is started again on the next reconnect (after the usual 1-15 s pause). To keep serve stopped (to run the desk in Rex), quit the app first. Once the app has loaded, a failed restart shows as offline and is retried; only a failed start at launch waits for Retry.
- Serve watches its own binary (every 2 s). Once `make install` replaces it, serve waits for the desk to finish its turn (10 minutes at most), stops as on SIGTERM and execs the new build with the same arguments: same pid and serve.log, a new port and token in a new `serve.json`. Clients see the stream close, read the new `serve.json` and fetch the snapshot again, so a new tracks never runs behind an old serve.
- Every request carries `Authorization: Bearer TOKEN`. Without it: 401.
- JSON in and out. Times are RFC 3339 UTC. Ids are strings.
- Reads are a snapshot plus a stream of changes (state, not events): a client renders the snapshot, then applies changes in order. On a gap (`seq` jumps) or reconnect it fetches the snapshot again.
- `seq` starts at the server's clock in milliseconds, so a restarted serve never reuses a seq a client saw: the first change after a restart reads as a gap. One serve runs per `TRACKS_HOME` (`serve.lock`); `serve.json` is removed when it stops.

## Reads

`GET /v1/snapshot` →

```json
{
  "seq": 1042,
  "generated_at": "2026-11-25T07:30:00Z",
  "desk": {"session": "c45dc3eb-…", "status": "idle", "queued_events": 2},
  "tracks": [{"id": "114", "name": "recipe-search", "goal": "…", "mode": "focus", "tier": "2", "rank": 1, "today": "PR 418 merged", "where": "…", "waiting_on": "", "check": {"text": "pr 418 approved", "answer": "no", "ran_at": "…"}, "links": ["https://…"], "blocked_by": [], "updated_at": "…"}],
  "sessions": [{"id": "7a8b070e-…", "short": "7a8b070e", "track": "114", "parent": "c45dc3eb-…", "owner": "desk", "host": "background", "name": "recipe-search", "status": "working", "waiting_for": "", "activity": "Bash: go test ./...", "subagents": [{"name": "PHP 8.5 delta rerun", "status": "working"}], "last_answer": "…", "changes": {"added": 212, "removed": 40, "files": 6, "branch": "emi-377", "merged": false}, "seen_at": null, "updated_at": "…"}],
  "questions": [{"id": "D14", "track": "114", "session": "7a8b070e-…", "from": "desk", "question": "Merge PR 418?", "options": [{"label": "Merge", "description": "CI green, approved"}, {"label": "Wait", "description": "…"}], "recommended": 0, "recommendation": null, "evidence": [{"text": "CI green on 3f2a1c", "source": "gh pr checks"}], "links": ["https://github.com/…/pull/418"], "attachments": [], "created_at": "…", "answer": null}],
  "conversation": [{"id": "m88", "at": "…", "role": "desk", "text": "…", "steps": 7}, {"id": "m89", "at": "…", "role": "emil", "text": "…"}, {"id": "m90", "at": "…", "role": "report", "session": "7a8b070e-…", "outcome": "done", "text": "…"}],
  "handled": [{"id": "e501", "at": "…", "track": "114", "kind": "nudged", "did": "…"}]
}
```

- A track's `check` is its `check:` line and the answer `tracks check` last recorded for it (EMI-431): `answer` is `"yes"` or `"no"`, and `answer` and `ran_at` are null until it has run. `check` is null when the track has none. When the answer changes on a track whose newest session the desk owns, `tracks check` wakes that session with a note (`[check] pr 418 approved`, held while it works) instead of adding an ask, so no question reaches the app for it.

- `desk.usage` is Emil's Claude usage limits for the usage bars at the foot of the app's sidebar (EMI-408): `{"five_hour": {"used_percentage": 42, "resets_at": "…"}, "seven_day": {…}, "updated_at": "…"}`, or null. Serve reads `$TRACKS_HOME/usage.json`, which Emil's Claude status line script writes from the `rate_limits` Claude Code hands it, at most once a minute; a change to the file sends the desk again. Either limit may be null, and `resets_at` is null when unknown. `updated_at` is when the status line last saw the numbers, so a client can tell stale ones (the app dims them after 10 minutes).

- `loop` is on a session the desk started as an overnight loop (`tracks start --loop`, EMI-466), and left out on every other: `{"turn": 3, "turns": 20, "until": "…", "state": "running", "paused_until": null}`. `turn` is the iteration running now (or the last one, once ended), `state` is `running`, `paused` (until `paused_until`, when the usage reached the loop's budget) or `ended`, and an ended loop carries `ended` with why in words. Serve reads it from `$TRACKS_HOME/loops/TRACK.json` and sends the session again when it changes. See docs/loops.md.
- `status` is one of `idle | working | done | blocked | error | stopped`; `done` with `seen_at` null is unread. A session that stopped stays in the list for 24 hours.
- `desk.status` is `idle`, `working` (in a turn) or `error` (its process died and serve is starting it again); `queued_events` counts Emil's messages and events waiting for the desk's next turn.
- `track`, `parent` and `session` are null when there is none, and `recommended` is null when a question recommends no option. `recommendation` is the recommendation in words (a question mirrored from a track's ask keeps its `Recommend:` text), or null. A question with no numbered options whose recommendation starts with yes or no gets the options Yes and No, with that one recommended; with no options and a recommendation, the client shows it as a row that answers `Go with your recommendation: <recommendation>`. `activity` is what the session's agent is doing now, one line cut to 80 characters (`Bash: go test ./...`, `Edit: serve.go`, `Agent: PHP 8.5 delta rerun`; `TOOL` alone for a tool with no short form), set by each tool call the session's own agent starts (a PreToolUse hook) and empty once its turn stops. `subagents` lists the subagents the session started: `name` is the Agent tool's description (else the subagent's type), `status` is `working` or `done`. A subagent stays `done` until the session's next prompt, and `[]` when there are none. Needs the PreToolUse, SubagentStart and SubagentStop hooks next to the others (schema 14); without them both stay empty.
- `delivery` is on a track agent's question (`from` `agent`, not a permission prompt) once it is answered: `"queued"` while Emil's answer is recorded and not yet typed into the agent, `"delivered"` once it was, `null` otherwise (open, closed without an answer, or a question of the desk's or a check's). A queued question stays in the snapshot however old it is, and leaves the board's Needs you group for "Answered, waiting to send". If serve cannot type the answer within 30 minutes the question is open again (`answer` null, `delivery` null) with a line in `evidence` saying why.
- `attachments` is the pictures, pages and files a question points at: `[{"label": "sheet.png", "url": "file:///Users/emil/x/sheet.png", "kind": "image"}]`, `[]` when none. `kind` is `image` (png, jpg, jpeg, gif, webp, svg, heic), `page` (html, htm, or an http(s) URL) or `file`; `url` is http(s) or `file://` (a path is made absolute, `~` expanded). An option may carry one of its own as `"attachment": {…}` (left out when none), so a visual choice reads as a row of pictures. They come from an ask's text: `See: PATH` once for the whole question, or `(see: PATH)` right after a numbered option; PATH is an absolute or `~/` path or an http(s) URL, and anything else stays in the text. The parser strips them from `question` and the option labels. The file may be missing by the time a client looks: show its path, not an error. Stored in the `questions.attachments` column (schema 12); an option's is inside `options`.
- Besides numbered options (`1) a 2) b`), a question's options come from one prose shape: the last sentence has a colon, then 3 to 9 items of 1 to 6 words separated by commas with a final "or" (or two items joined by "or"), ending in "?", as in `Which icon: owl, parcel, round trip or mended parcel?`. The recommendation picks the option whose label it starts with.
- `changes` is null until serve has read it (git runs off the request path, at most once a minute per folder) and outside a git repository or on `main` itself. It counts the committed work since the branch left `main` (or `master`); git runs with no fsmonitor, hooks, external diff or textconv, and never reads the working tree; `merged` is true when the branch's head is in `main` and nothing differs.
- Option numbers count from 0, in `recommended` and in an answer's `option`. A question is open while `answer` is null; once answered it is `{"option": 0, "text": null, "by": "emil", "at": "…"}` (or `{"note": "…", "by": "", "at": …}` when closed). Answered and closed questions stay for 24 hours.
- `conversation` holds the desk's chat, newest last, the last 200 entries; `GET /v1/conversation?before=m88` pages back and answers `{"conversation": [...]}`, oldest first. `role` is `desk`, `emil` or `report`; a desk entry's tool calls are folded into `steps`. A desk entry grows while its turn runs, as upserts of the same id. `steps`, `session` and `outcome` are left out when empty. A desk entry with `outcome: "reasked"` numbered questions in chat and was hidden by the server: clients show it collapsed, and the desk raises its questions again as decisions. Clients show each `D` id a desk entry names as a chip for that question.
- `handled[].track` is the track's id while the track is open, else its name. `handled[].undone` is true once Emil took the entry back; the app shows a Reopen (closes) or Take back (answers, starts) button on the others.

`GET /v1/events?since=SEQ` is a Server-Sent Events stream. Each event: `id: SEQ`, `data: {"seq": N, "op": "upsert" | "remove", "kind": "track" | "session" | "question" | "conversation" | "handled" | "desk", "value": {…}}` (`remove` carries `{"id": …}`; `conversation` and `handled` are windows of the newest entries and never send `remove`). A comment line every 15 s keeps it open. When `since` is older than the changes serve still keeps (2000), or newer than its `seq`, the stream closes at once: fetch the snapshot again.

`GET /v1/sessions/{id}/transcript` → `{"entries": [{"role": "user" | "assistant" | "report", "text": "…", "steps": 3, "at": "…"}]}` from Claude's JSONL, tool calls folded into `steps`, the last 300 entries.

## Actions

| Request | Body | Does |
|---|---|---|
| `POST /v1/desk/messages` | `{"text": "…"}` | Emil writes to the desk. Queued if the desk is in a turn; delivered as the next turn. 202 with the conversation entry. |
| `POST /v1/desk/restart` | `{}` or `{"desk_token": "…"}` | Ends the headless desk's session and starts a fresh `/desk headless` one, whose first message carries the newest `HAND-OFF` entry of the handled log. What queued for the desk waits and goes in after that first turn. 409 while the desk is in a turn; with the desk's own secret (the desk running `prism desk restart`) it restarts once that turn ends instead. 202 with `{"status": "…"}`. |
| `POST /v1/questions/{id}/answer` | `{"option": 1}` or `{"text": "…"}` | Records Emil's answer and delivers it to the owner (desk or the track's session). The 5-second undo lives in the client: it sends this only when the countdown ends. Answers `{"status": "answered D9: …", "delivery": "delivered"}`; when the track's agent is working or waiting on a prompt, nothing is typed: the answer is recorded and `{"status": "queued D9: typed into TRACK when its agent stops", "delivery": "queued"}` comes back, and serve types it once Rex reports the agent idle or done (one answer per track at a time, a failing try repeated at most once a minute, given up after 30 minutes). Without serve running, `tracks decide` records the same and the next serve start delivers. Any other refusal (no session, the agent gone or failing) is still an error and records nothing. 409 if already answered. |
| `POST /v1/answers` | `{"answers": [{"id": "D9", "option": 1}, {"id": "D10", "text": "…"}]}` | One asker's answers (the same track, else the same session; no permission prompts), recorded and delivered as ONE message: `Emil's answers:` then one line per answer in the form a single answer is typed in (`Emil's answer to your ask 1, "…": …`), typed into the track's agent on one line, or as one `tracks send` note to a session the desk started. Nothing is recorded when any answer is refused (404, 409 for one already answered, 400 for a bad option, an empty answer, two askers or a message over 2000 characters). A busy agent gets them as one queued delivery: the answers are recorded with the same `answered_at` and serve types them as one message when the agent stops. Answers `{"status": "answered D9, D10", "delivery": "delivered"}` or `"queued"` as the answer route does. The app stages answers for an asker with several open questions, and sends this once the last is staged or Emil presses "Send N answers" (⌘↩), after the usual 5-second undo. |
| `POST /v1/questions/{id}/ask` | `{"text": "…"}` or `{"show_options": true}` | Asks the agent about its question without answering it; the question stays open. The agent is told `Emil asks about your ask "…": TEXT` (the ask quoted as an answer quotes it), typed or sent as a note by the same paths as an answer. `show_options` sends `Render each option of your ask "…" to an image and ask again with (see: PATH) after each option, but only if the options are visual (icons, colours, layouts, screenshots). If they are words or plans an image can't show, say so in one line and leave your ask as it is.` and needs options (400 without). A question of the desk's or a check's goes to the desk as a message. A permission prompt is refused (400). A busy track agent gets it queued: serve holds the ask in memory and types it when the agent stops (a restart of serve drops it), given up after 30 minutes. Answers `{"status": "asked about D9", "delivery": "delivered"}` or `"queued"`. |
| `POST /v1/questions/{id}/close` | `{"note": "…"}` | Closes it without an answer. |
| `POST /v1/sessions/{id}/takeover` | none | 409 for the desk's own session. Owner becomes emil; opens `claude attach SHORT` in a new Rex tab (`rex`), or answers `{"command": "claude attach SHORT"}` when Rex isn't there. |
| `POST /v1/sessions/{id}/giveback` | none | Owner becomes desk; the desk is told once. |
| `POST /v1/sessions/{id}/seen` | none | Sets `seen_at` (the client calls it when Emil opens the session). |
| `POST /v1/sessions/{id}/stop` | none | `claude stop SHORT`. |
| `POST /v1/tracks/{id}/mode` | `{"mode": "focus", "swap": "NAME"}` | As `tracks mode`. A third focus track answers 409 `{"error": …, "focus": ["older", "newer"]}`; send it again with `swap` naming the focus track that moves to background. A track's `shown_mode` in the snapshot is the mode it is shown in: waiting is computed (a `check` or `waiting_on`, no open ask, no working session), and a stored `waiting` reads as background (EMI-423). |
| `POST /v1/tracks/{id}/open` | none | As `tracks open`: focus its Rex session. |
| `POST /v1/tracks/{id}/loop/stop` | none | As `tracks loop stop NAME` (EMI-466): the track's loop ends after its current turn, a paused one at the watch's next look; its session is not stopped. Answers `{"status": "NAME's loop ends after its current turn; its session is not stopped"}`; 404 when the track has no live loop (none, or one that ended). |
| `POST /v1/handled/{id}/undo` | none | As `u` in the pane's handled log (EMI-420): takes back the desk's entry (`e501`). A `closed` entry opens the track again with its card as it was; an `answered` one tells the track to disregard the desk's answer; a `started` one closes a track that had not started work. Answers `{"status": "Reopened NAME: its card is back, enter opens it"}` (or the pane's refusal text, such as `Not taken back: …`, with 200). 400 for any other kind, 404 for no such entry, 409 for one taken back already. |

Other actions answer `{}`; takeover answers `{}` when it opened the Rex session. Errors: `{"error": "…"}` with 400, 401, 404, 409 or 500.

## The desk behind serve

`prism server` (without `--mock`) runs the desk as `claude -p --input-format stream-json --output-format stream-json --verbose --model $TRACKS_DESK_MODEL` (default opus) in `~/Developer`, first with `/desk headless`, later with `--resume` of the session it recorded (`desk.claude_session`, schema 11). It binds the desk to `tracks-serve` (refused while an interactive desk's agent runs in Rex, unless `--force`). Each start of the desk's process gets a new secret in its environment (`TRACKS_DESK_TOKEN`, stripped from the sessions the desk starts); a command acts as the desk only when serve confirms that secret over `POST /internal/desk` (`Authorization: Desk SECRET`, 204 or 403), so neither the environment flag alone nor anything written to `serve.json` makes a process the desk. Nothing is written to the desk during a turn: Emil's messages and events queue, and after the turn's `result` go in as one message, `Emil: …` lines first, then `Events:` with one `- …` line each. Serve does the watch's work itself (held notes, reports, status changes, answers to the desk's questions, the start queue), so the headless desk runs no Monitor. A desk process that dies is started again after 1 s, doubling to a minute; meanwhile `desk.status` is `error`.

Serve keeps long contexts short with Claude Code's own `/compact`, at quiet moments only (EMI-448, EMI-451). When a desk turn ends with the desk's last call past 150k tokens of context, serve sends `/compact` as the desk's next turn (`desk.status` `working`), and what queued goes in after it. A session the desk started is compacted before its next note: when a held note is due and the session's transcript puts its last call past 250k, the watch resumes it with `/compact` instead, marks it in `$TRACKS_HOME/compacting/ID`, and delivers the note once a compaction shows in the transcript (or after 10 minutes). `tracks send` and answers to such a session are held for the watch the same way. The session keeps its id, card and reports.

## Mock

`mock/serve-fixture.json` holds a snapshot with the mockup's content (recipe-search D14 with options and evidence, scanner-skips-shop-api D15 blocked on a permission prompt, bun-rollout, pantry-api working, queue-api ready to land, weekly-brief as Emil's, invoice-export waiting on Alex). The app's tests and previews read it, and `prism server --mock FILE` (step 5) serves it with the same routes, answering actions in memory. `mock/serve-transcripts.json` beside it maps session ids to `/v1/sessions/{id}/transcript` answers. The app runs on both with `Desk --fixture mock/serve-fixture.json`.
